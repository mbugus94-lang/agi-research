## Research synthesis

The current two-week research signal continues to favor typed state, explicit provenance, compiled execution boundaries, and review-gated self-improvement:

- **NexForge** (arXiv:2607.14186) uses requirement-first, executable task synthesis and reports large benchmark gains from reproducible task construction.
- **Operational Hallucination and Safety Drift in AI Agents** (arXiv:2607.18366) identifies reasoning/execution-state divergence and motivates explicit runtime checks plus forced termination.
- **PoTRE** (arXiv:2607.20268) uses heterogeneous specialist agents and task-adaptive aggregation, reinforcing separation of proposal, refinement, search, and verification roles.
- **SIGIL: Compiling Agent Skills into Typed Harnesses** (Zenodo, July 22, 2026) reports higher procedural compliance when prose skills are compiled into typed executable harnesses rather than reconstructed by the model.
- **Knowledge-Centric Self-Improvement** (arXiv:2607.19592) keeps improvement in a curated knowledge layer instead of silently mutating the agent.
- **Native Python Object-Oriented Agents** (arXiv:2607.20709) makes state, capabilities, and contracts inspectable objects.

Open-source activity signals included `agentscope-ai/AgentTeams` (manager-workers with human visibility), `desplega-ai/agent-swarm` (isolated workers and shared learnings), and `Panniantong/Agent-Reach` (audited multi-source agent access). These are architecture/activity signals, not a controlled popularity ranking.

## Build

Closed the previous run's next priority by extending `cli/cage1_review.py` with verification-only signed operator-decision handling:

- Added repeated `--decision-envelope` inputs.
- Added `--decision-key-id`, `--decision-hmac-secret`, optional hexadecimal secret mode, and `--decision-now` for signature/expiry verification.
- Added optional `--decision-report-out` for a machine-readable verification report.
- The CLI now verifies each signed decision against the generated advisory and the original raw source envelope before reporting it.
- Invalid, expired, conflicting, ambiguous, and missing evidence remain visible through the existing consumer report; no decision is selected unless the join is valid.
- Exit status is `0` only for a valid advisory/evidence/single-decision join, `1` for a verification failure, and `2` for malformed CLI input or unreadable records.
- Extended `experiments/test_cage1_review_decision.py` with valid, tampered, and missing-credential coverage.

Safety boundary: the CLI only verifies and reports. It never applies `accept`, `reject`, or `defer`, changes policy, repairs evidence, mutates code, or triggers self-improvement. `decision_applied=False` and `automatic_action_taken=False` remain enforced by the consumer.
